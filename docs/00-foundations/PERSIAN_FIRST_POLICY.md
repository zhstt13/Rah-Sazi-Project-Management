# سیاست فارسی‌سازی اول

## هدف

زبان پیش‌فرض این پروژه برای مدیر، کارفرما، مشاور، دفتر فنی و کارگاه فارسی است. این سیاست از بازگشت تدریجی متن انگلیسی جلوگیری می‌کند.

## چه چیزهایی باید فارسی باشند؟

- عنوان و متن README؛
- مستندات، راهنماها و چک‌لیست‌ها؛
- متن قابل‌نمایش داشبورد؛
- عنوان و توضیح فرم‌های GitHub؛
- Placeholder و گزینه‌های فرم؛
- متن گزارش و دادهٔ نمونه؛
- پیام خطا و خروجی ابزارها؛
- عنوان، توضیح و راهنمای schemaها؛
- متن Commit و PR تا جایی که با روند فنی تعارض نداشته باشد.

## چه چیزهایی فعلاً انگلیسی می‌مانند؟

- نام فایل و مسیر فنی؛
- کلیدهای JSON و YAML؛
- نام تابع و کلاس؛
- پرچم خط فرمان؛
- شناسهٔ GitHub Action؛
- شناسهٔ رکورد و کد WBS/BOQ/CBS؛
- مقدارهای enum ماشین‌خوان در صورتی که تغییرشان قرارداد نرم‌افزاری را بشکند.

برای هر مقدار فنی، در لایهٔ نمایشی عنوان فارسی اضافه کنید.

## آزمون زبان

هر Release باید این موارد را بررسی کند:

- جست‌وجوی متن انگلیسی قابل‌مشاهده؛
- بازکردن README و dashboard روی گوشی؛
- بررسی جهت راست‌به‌چپ، اعداد، تاریخ و جدول‌ها؛
- بررسی فرم‌ها در GitHub؛
- بررسی اینکه ترجمهٔ متن، کلید و محاسبه را تغییر نداده باشد.

## معیار پذیرش

فارسی‌سازی وقتی پذیرفته است که کاربر ایرانی بدون نیاز به خواندن انگلیسی بتواند هدف پروژه، وضعیت پروژه، اقدام بعدی و مدرک هر تصمیم را بفهمد.
