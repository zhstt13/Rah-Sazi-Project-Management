# مدیریت پروژه راه‌سازی

> یک سیستم عامل مدیریتی فارسی، قابل‌ردیابی و مبتنی بر مدرک برای پروژه‌های راه و زیرساخت.

این ریپو قرار است پروژهٔ راه‌سازی را از تعریف محدوده تا تحویل نهایی قابل‌کنترل کند: ساختار شکست کار، فهرست‌بها، زمان‌بندی، هزینه، پیشرفت، ریسک، تغییر، قرارداد، خرید، کیفیت، HSE، محیط‌زیست، حریم و تأسیسات، نقشه‌برداری، GIS/BIM، اسناد، گزارش، تحویل و درس‌آموخته‌ها.

## وضعیت فعلی

این نسخه «هستهٔ اولیهٔ سیستم» است و هنوز محصول کامل سازمانی یا جایگزین نرم‌افزارهای تخصصی زمان‌بندی، مالی، CDE، GIS، BIM یا حسابداری نیست.

داده‌های پروژهٔ نمونه فرضی‌اند و فقط برای نمایش ساختار، تست محاسبات و نمایش داشبورد استفاده می‌شوند.

## قانون اصلی

تمام متن‌های قابل‌مشاهدهٔ پروژه باید فارسی باشند.

نام فایل‌ها، کلیدهای JSON، نام توابع، پرچم‌های خط فرمان، شناسه‌های GitHub و کدهای فنی انگلیسی حفظ می‌شوند تا اتصال نرم‌افزاری و اعتبارسنجی خراب نشود. این موارد لایهٔ ماشین‌خوان هستند، نه متن ارائه به کاربر.

## از کجا شروع کنیم؟

1. ابتدا [چک‌لیست جامع فارسی](CHECKLIST_FA.md) را بخوانید.
2. سپس [معماری سیستم](ARCHITECTURE.md) و [نقشهٔ ریپو](REPOSITORY_MAP.md) را ببینید.
3. برای قوانین زبان و بومی‌سازی به docs/00-foundations/PERSIAN_FIRST_POLICY.md بروید.
4. پروژهٔ نمونه در data/examples/demo-road-project قرار دارد.
5. قالب‌های ثبت ریسک، گزارش روزانه، تغییر، تصمیم و بازرسی در templates/records قرار دارند.
6. داشبورد نمایشی در apps/dashboard/index.html است.
7. اعتبارسنجی با ابزار tools/validate_repository.py انجام می‌شود.

## چیزهایی که این ریپو پوشش می‌دهد

| حوزه | خروجی |
|---|---|
| تعریف و حاکمیت | چرخهٔ عمر، دروازه‌ها، نقش‌ها و RACI |
| محدوده و ارزش | WBS، BOQ، CBS و کدهای هزینه |
| زمان | خط مبنا، مسیر بحرانی، Look-ahead و برنامهٔ جبرانی |
| هزینه و پیشرفت | PV، EV، AC، SPI، CPI، EAC و ETC |
| عدم‌قطعیت | ریسک، مسئله، فرصت، محدودیت و اقدام |
| تغییر و قرارداد | Change Request، Claim، Variation و پرداخت |
| کیفیت | ITP، Hold Point، آزمایش، NCR و اقدام اصلاحی |
| HSE | خطر، مجوز، ترافیک، حادثه و محیط‌زیست |
| منابع و تأمین | خرید، مصالح، ماشین‌آلات و تأمین‌کننده |
| رابط‌ها | زمین، حریم، تأسیسات، ذی‌نفعان و جامعه |
| اطلاعات | Document Control، Transmittal، GIS و BIM |
| پایان پروژه | راه‌اندازی، تحویل، گارانتی و درس‌آموخته |

## مرز سیستم

GitHub لایهٔ همکاری و سابقهٔ تغییرات است. سیستم تخصصی زمان‌بندی، حسابداری، مدیریت اسناد، GIS، BIM یا ثبت میدانی می‌تواند مرجع جزئیات خودش بماند. در این ریپو باید شناسهٔ منبع، تاریخ Snapshot، ویرایش و مدرک ثبت شود.

## وضعیت انتشار

انتشار فعلی تا تکمیل چک‌لیست فارسی، اتصال واقعی داشبورد به داده، انتخاب مجوز و بازبینی امنیتی، نسخهٔ نهایی محسوب نمی‌شود.
